# 算法原理与实现

本文对应仓库当前代码；逐步命令见 [操作手册](WORKFLOW.zh-CN.md)，本次参数与实测数值见 [索尼案例](SONY_CASE.zh-CN.md)。

## 1. 将问题拆成几何、颜色与输出

照片拼接需要同时解决三个问题：同一景物在不同照片中的位置如何对应，重叠区域的颜色如何一致，以及有限内存下如何生成完整文件。单纯增大输出尺寸不能改善配准，融合接缝也不能修正错误的相机姿态。

本流程先估计相机旋转和镜头参数，再做全局调平与光度处理，最后重投影和融合。没有加入神经网络、局部弹性形变或生成式填补。相机模型假设照片主要由原地旋转获得；近景视差、人物运动、海浪和云层运动仍可能导致局部不一致。

两条已测路线的差别如下：

| 阶段 | Sony ARW 普通相机 | DJI JPEG 球面全景 |
|---|---|---|
| 几何初值 | EXIF 焦距 + 图像对应点估计旋转 | 完整的云台 yaw/pitch/roll 元数据 |
| 颜色基础 | 所有 RAW 使用同一白平衡和显影策略 | 保留相机已处理的 JPEG 色调 |
| 困难区域 | 海天重叠补充特征，并验证旋转一致性 | 无纹理纯天空可能保留云台姿态先验 |
| 光度校正 | 拟合曝光，可选镜头暗角 | 天空 RGB 平滑补偿网格，地面保持固定 |
| 输出 | 实际覆盖的圆柱长条 | 360×180° 等距柱状画布 |

## 2. RAW 显影与配准工作图

实现：[prepare_raw.py](../Hugin_test/prepare_raw.py)。目前该入口读取 Sony `.ARW`，不是所有 RAW 格式的通用转换器。

1. 按文件名排序，检查相机、镜头、焦距、快门、光圈、ISO、方向与白平衡标签。EXIF 通过 ExifTool 的 UTF-8 参数文件读取，避免 Windows 中文路径被 ANSI 编码破坏。
2. 从 ARW 提取嵌入 JPEG，制作带零起始编号的联系表。这些小图只用于选图和观察顺序，不作为最终拼接源图。
3. 读取所有照片的 `WB_RGGBLevels`，对各分量取中位数，以绿色归一化，再把 Sony 的 `R,G,G2,B` 顺序转换为 LibRaw 所需的 `R,G,B,G2`。所有照片共用这组白平衡，避免逐张自动白平衡制造新的接缝。
4. 使用 rawpy/LibRaw 的 AHD 去马赛克，输出 16 位 sRGB，关闭自动增亮，`bright=1.0`，gamma 参数为 `(2.4,12.92)`。写入带 sRGB ICC 的全尺寸 RGB TIFF。输出已是带传递曲线的颜色图像，并非线性 RAW。
5. 从全尺寸 RGB 数组每隔 3 个像素抽样，转换成 8 位、质量 97、4:4:4 的工作 JPEG。正确写入 Exif IFD，让 Hugin 能读取焦距和曝光等参数。原尺寸 TIFF 保留用于最后重投影。

工作图当前采用 `rgb[::3, ::3]`，不是带抗混叠滤波的缩小。这是速度与精度的折中，细小重复纹理可能混叠。全尺寸项目提升采用像素中心比例换算，与这种抽样的精确像素位置存在小差别；因此必须检查提升后的原尺寸残差，不能把工作图误差直接当作原图误差。

显影时记录原 ARW 的 SHA256、大小和时间戳；缓存复用检查源文件状态及显影策略。输入目录或显影设置改变后应使用新工作目录。已过曝的信息不会因写成 16 位 TIFF 而恢复，这一流程也没有进行 HDR 合成。

参数含义参见 [rawpy 官方 Params 文档](https://letmaik.github.io/rawpy/api/rawpy.Params.html)。

## 3. 特征、控制点与普通相机旋转初值

### 3.1 先取得可信的对应点

[stitch.py](../Hugin_test/stitch.py) 调用 `pto_gen` 建立 PTO 工程。`i` 行记录图像、镜头和姿态，`c` 行记录控制点，`v` 行声明本次允许优化的参数。字段解析支持整数、小数、科学计数法和 `v=0` 这类链接，不用宽泛的数字替换误改曝光或文件名。

有 DJI 姿态时，cpfind 使用 `--prealigned` 和旋转模式筛选；没有姿态时，使用 `--multirow` 和单应性候选筛选。本次普通相机案例额外显式运行 `--allpairs`，让首尾闭环及困难重叠有机会被发现。

海面、薄雾和纯天空纹理很弱，单应性也可能在错误对应点上拟合得很好。[supplement_matches.py](../Hugin_test/supplement_matches.py) 对指定图像对执行：

- 灰度 CLAHE 增强，仅作用于特征检测图，不改变最终颜色。
- SIFT 检测，双向最近邻匹配和 0.78 比值筛选。
- USAC_MAGSAC 单应性筛选，阈值 2.5 工作图像素。
- 每个 150 像素网格最多保留 3 点，避免点都集中在同一小片区域。

单应性在这里用于筛选候选对应，不直接作为最终全景变换。补点的照片编号来自本次联系表，不是可以通用于另一组照片的固定参数。[OpenCV SIFT 文档](https://docs.opencv.org/4.x/d7/d60/classcv_1_1SIFT.html) 说明了特征检测器接口。

### 3.2 把二维点变成相机射线

实现：[camera_alignment.py](../Hugin_test/camera_alignment.py)。对宽度为 $w$、水平视场角为 $v$ 的直线投影相机，焦距的像素表示为：

$$f=\frac{w}{2\tan(v/2)}$$

按代码使用的前、左、上基底，坐标为 $(x,y)$ 的像素对应单位射线：

$$\mathbf u=\operatorname{normalize}\left(1,-\frac{x+0.5-w/2}{f},-\frac{y+0.5-h/2}{f}\right)$$

`+0.5` 表示像素中心。Hugin 变换与验证统一使用这一约定，尤其避免高纬度球面区域的误差被错误度量。

对于相邻照片 A、B，估计一个三维旋转 $R$，使 $R\mathbf u_B$ 接近 $\mathbf u_A$。用 Kabsch/SVD 拟合，并通过行列式修正保证旋转属于 SO(3)，不会产生镜像变换。

RANSAC 使用固定随机种子、400 次三点抽样，以“射线弦长差 × 平均焦距”小于 8 工作图像素为内点标准，再重拟合。至少 8 个内点且旋转角合理才接受该图像对。初始化不拟合畸变，后续由 Hugin 全局优化镜头参数。

### 3.3 用强连接建立整圈姿态

图像是节点，可信对应关系是边，边权为内点数量。无姿态先验时，必须形成一个连通图；缺失连接就停止并报告分量，不能把孤立照片随意放进画布。

从图像 0 开始，沿最大生成树传播旋转，优先使用支持点多的连接。生成树只提供初值，之后 Hugin 的全局优化使用全部保留控制点，包括首尾闭环。这样既避免狭窄重叠中不稳定的逐对姿态翻转，又能利用整圈约束消除累计漂移。

## 4. 全局几何优化与离群点清理

每个连通分量固定一个姿态锚点，其他图像优化 yaw、pitch、roll；可选优化每个镜头组的 HFOV 和径向畸变系数 `b`。本次 Sony 焦距有 119、126、129 mm 三组，分别共享镜头参数，不能强制所有照片用同一个视场角。

代码显式写入优化变量，再调用 `autooptimiser -n`。`--optimize-distortion` 只增加几何畸变参数 `b`；它与光度模型中的 `Vb` 完全不同，前者改变位置，后者描述亮度随半径的变化。

先进行 `cpclean --pairwise-checking`，全局拟合后，再按中位数和 MAD 清理过大残差：

$$T=\max\left(8,\min\left(24,\operatorname{median}(e)+3\times1.4826\times\operatorname{MAD}(e)\right)\right)$$

删除超阈值点，以及清理后不足 8 个点的图像对，再拟合和检查连通性。阈值用于第一轮结果，第二轮重新拟合后的最大残差仍可能略高于这个阈值，并不矛盾。

几何保护还检查有限数值、1–179° 的直线投影 HFOV，以及相对 DJI 先验的姿态偏移。普通相机没有可作为真值的云台姿态，因此不能使用相同的先验偏移判断。

报告残差使用 Hugin 原生投影得到两条世界射线的夹角，再乘以对应源图的平均像素焦距。工作图阶段单位是工作图等效像素，提升到 TIFF 后是原图等效像素。它们是参与拟合的控制点残差，不是独立测量精度，也不等于最终画布上所有位置的像素误差。

## 5. 默认自动地平线矫正

实现：[horizon.py](../Hugin_test/horizon.py)。`--level-horizon auto` 默认开启，可用 `off` 关闭，或用 `hugin` 强制选择原生 straighten。

自动模式先找控制点支持的最大分量中俯仰角接近水平的拍摄环：至少 8 张，绝对 pitch 不大于 10°，yaw 覆盖不小于 240°。将相机光轴映射到单位球，鲁棒拟合平面：

$$y=ax+bz+c$$

这里使用右、上、前的球面坐标。斜率决定需要校正的倾斜，截距保留拍摄环的平均仰俯角，避免把本来向上拍摄的整圈强行压到零度。拟合经过 8 轮 Huber 加权；残差过大或覆盖不足时，退回 `pano_modify --straighten`。

最终只接受同一个全局三维旋转 $Q$：

$$M_i^{\mathrm{after}}=Q M_i^{\mathrm{before}}\quad\text{对所有照片 }i$$

代码限制自动转角不超过 5°，逐张检查矩阵最大误差不超过 $10^{-7}$，并且只复制 Hugin 输出的 yaw/pitch/roll，保留镜头、颜色和控制点字段。非零相机平移的工程会被拒绝。

这一方法依赖“拍摄环大致等高”等几何假设，**没有识别画面里的海平线，也没有独立测量重力方向**。自动调平后仍应看预览；有明显俯仰变化、山脊线或非水平建筑时，不应把轮廓形状直接当作地平线。本次 Sony 使用 Hugin 后备方法，全局旋转约 1.2083°。

## 6. 天空色差与暗角如何处理

### 6.1 原因不能只归结为一个参数

暗角主要表现为同一张照片边缘比中心暗，白平衡变化更容易表现为整张照片色调不同；自动曝光、机内色调曲线、太阳方向和云层变化也会叠加。本次 DJI 原片元数据为自动白平衡，记录的色温约 4687–8598 K，并伴随曝光变化。这支持“逐张颜色策略变化参与了色差”的判断，但不足以排除镜头暗角，更不能据此精确拆分两者贡献。

### 6.2 RAW：先统一白平衡，再拟合曝光与暗角

[prepare_camera_project.py](../Hugin_test/prepare_camera_project.py) 以第一张曝光为参考，仅拟合其余图像的曝光；指定 `--vignetting` 时再拟合每个镜头组的 `Vb/Vc/Vd`。白平衡保持 RAW 阶段的统一结果，不逐张自由调整。

径向亮度模型的采样形式为：

$$V(r)=V_a+V_b r^2+V_c r^4+V_d r^6$$

实际光度变换交由 Hugin 完成。代码在 $r=0,0.25,0.5,0.75,1$ 采样，要求因子在 0.4–1.5 之间；这是异常值保护，不是独立标定，也不保证连续区间内所有值都经过检查。

本次使用 `vig_optimize -s 1 -p 600` 从重叠区域拟合，全局输出提亮 1 EV；后者是本组图像的显示选择，不代表其他场景都应提亮。具体输出曝光符号由 Hugin PTO 约定决定，脚本把 `--brightness-stops 1` 写成输出 `E=-1`。参见 [Hugin 光度优化文档](https://hugin.sourceforge.io/docs/manual/Vig_optimize.html)。

### 6.3 DJI JPEG：受约束的天空颜色网格

[balance_sky.py](../Hugin_test/balance_sky.py) 用相机几何选出整张视野高于地平线 2° 的照片，把地面与跨地平线照片固定为颜色参照。它是几何选择器，不是语义天空分割。当前要求居中、无畸变的直线投影源图及中性的光度参数，不能直接用于已拟合 `b` 的 Sony 工程。

每张天空图像的每个颜色通道有一个 4×4 网格，以双线性插值得到位置相关的加性偏移：

$$I'_i(x,y,c)=\operatorname{clip}(I_i(x,y,c)+B_i(x,y,c),0,1)$$

针对同一重叠位置，求解 $B_i-B_j\approx I_j-I_i$。使用稀疏最小二乘、幅度约束、一阶与二阶平滑正则，及 8 轮 Huber IRLS；连向固定参照照片的样本权重更高。所有待校正照片必须存在通向固定颜色参照的重叠路径。

样本按图像对分组打乱，每对最多取 18 个且约不超过三分之一用于训练，其余留作验证，至少保留 50 个验证样本。验证均值必须改善，P95 不得恶化，模型必须有限且最大绝对偏移不超过 0.45；新增饱和通道值比例超过 0.5% 时拒绝写出。

校正作用于**已编码 JPEG RGB 数值**，不是线性光照估计或物理白平衡解算。原尺寸补偿图写成 16 位 TIFF，以减少后续处理的再次量化；源 JPEG 保持不变。报告中颜色差是每个样本 RGB 三通道绝对差的平均值，折算为 0–255 色阶，不是感知色差 ΔE。

## 7. 投影、原生分辨率与裁切

忽略中心偏移与符号约定，等距柱状投影可写成 $x=f\theta,\ y=f\phi$，圆柱投影可写成 $x=f\theta,\ y=f\tan\phi$。前者适合表达完整经纬度球面；后者适合水平范围很广、上下范围较窄的长条。

Sony 案例覆盖水平一圈，但没有拍到天顶和脚下，所以采用圆柱 `f=1, v=360`。不补成 2:1，也不添加球面 GPano 标签。拍摄不足一圈时应使用实际视场角和有限边界；当前 `prepare_camera_project.py` 的圆柱 360° 与 yaw 171° 是此案例的配置，需要修改后才能适用于其他覆盖范围。171° 只选择画面起始方向，不是调平角。

最终将 PTO 源图换成原尺寸 TIFF，更新宽高、像素偏移和控制点坐标，例如：

$$x_{\mathrm{full}}=(x_{\mathrm{small}}+0.5)s_x-0.5$$

然后通过 `pano_modify --canvas=AUTO --crop=AUTO` 得到原图采样密度的画布和实际裁切框。不同尺寸下的自动裁切可能得出不同范围，所以预览裁切框由原生裁切框按比例换算，确保预览与最终覆盖一致。当前提升代码拒绝源图裁切与掩模，避免未经换算的坐标被误用。命令含义见 [Hugin pano_modify 文档](https://hugin.sourceforge.io/docs/manual/Pano_modify.html)。

## 8. 分块重投影、融合和导出

实现：[export_jpg.py](../Hugin_test/export_jpg.py)、[export_flat.py](../Hugin_test/export_flat.py)。

1. 默认以 4096 像素为块核心划分画布。需要拼块时，周边增加保护区和羽化区；相邻块有 512 像素重叠。
2. Nona 把源图重投影成 16 位 RGBA 图层。8 位 JPEG 与 16 位 TIFF 按输入位深分组调用，输出统一为 UINT16，避免 Nona 混合位深限制。
3. Enblend 在块内进行接缝选择与多分辨率融合。只有已识别的窄边缘接缝错误才尝试原生细掩模后备参数，其他错误直接停止并保留日志。
4. 360° 完整圆柱或球面在水平方向周期连接。通过所有相机共同旋转，将边界移到画布中间渲染；位移是整数画布像素对应的 yaw。非整圈或横向裁切的画布使用有限边界，不首尾拼接。
5. 块间按透明度参与加权的 RGB 羽化混合，alpha 取覆盖较大值，避免无覆盖区域把边缘变黑。不同宽度的块精确拼接，不补成等宽单元。
6. libvips 按需读取并写入工作条带，再流式编码成品。输入 PTO 哈希、源图大小/时间戳、块大小和编码设置记录在状态文件中，续算时必须匹配。最后完整解码检查，而不只检查文件是否存在。

分块处理降低峰值内存，但每块独立选择接缝，因此不承诺与一次性整图 Enblend 输出逐像素一致。动态物体或细小几何不一致仍需原尺寸查看。[libvips 工作原理](https://www.libvips.org/API/current/how-it-works.html) 介绍了按需计算机制。

球面导出器要求完整 2:1 画布，超出本实现采用的 libjpeg 65500 像素限制时拒绝导出，要求显式调整尺寸。长条导出器保留原 PTO 投影与裁切：若任一边超限，则生成连续 16 位 BigTIFF、每边不超过 60000 像素的原像素 JPG 分段，以及最长边 65000 的缩小便览图。

JPG 默认质量 97、4:4:4、8 位 sRGB。**全像素 JPG 仍是有损文件**；16 位 BigTIFF 保存融合后的高位深母版，也不等于原始 RAW。未覆盖区域只能用背景色表示，代码不会生成新的景物。
