# Sony A7R V「日光岩全景2」案例

本案例是一次已完成的本机处理记录。照片、PTO、成品大图和运行缓存不随公开仓库上传；操作命令见 [完整手册](WORKFLOW.zh-CN.md)，去除本机路径后的数值摘录见 [案例 JSON](examples/sony_riguangyan2_summary.json)。

## 输入与目标

| 项目 | 本组数据 |
|---|---|
| 相机 | Sony A7R V，EXIF 型号 ILCE-7RM5 |
| 镜头 | Tamron E 35–150mm F2.0–F2.8 A058 |
| 文件 | 38 张 ARW，GUA01805–GUA01842，按文件名排序 |
| 焦距 | 119 / 126 / 129 mm，共三组 |
| 拍摄参数 | F6.3、ISO 125、快门约 1/1250–1/400 秒 |
| 原片总体积 | 约 4.85 GB |
| LibRaw 有效显影尺寸 | 每张 9564×6376，16 位 RGB |
| 配准工作图 | 每张 3188×2126，8 位 JPEG |
| 覆盖 | 水平一圈，垂直范围很窄 |
| 目标 | 圆柱长条，保持原图采样密度，不扩成球面 |

ARW 元数据中的记录尺寸与 LibRaw 的有效显影尺寸不完全相同；最终使用实际输出数组的宽高，不把 9600 像素等 EXIF 尺寸直接套到已显影图像上。

## 最终使用的处理方法

所有 RAW 使用中位数统一白平衡，LibRaw 顺序的 `R,G,B,G2` 增益为 `[2.6650390625, 1, 1.5615234375, 1]`。AHD 去马赛克，关闭自动增亮，写成 16 位 sRGB TIFF；配准使用同一显影结果的约三分之一尺寸工作图。

cpfind 全图像对匹配后，为困难海面区域的零起始图像对 `24-25,25-26,26-27,27-28` 补点。这四对分别新增 39、12、11、55 个候选控制点，仍要经过后续几何筛选，不能把补点数量直接视为最终有效点数。

通过标定射线的 RANSAC 旋转拟合和最大生成树取得姿态初值；随后优化全局旋转、各镜头组 HFOV 和径向 `b`，清理离群点后再拟合。最终 38 张照片全部在一个连通分量中，保留 1234 个控制点、40 个匹配图像对，没有依赖 DJI 姿态。

| 镜头组首图编号（零起始） | 源焦距 | 优化后 HFOV | 几何径向系数 b |
|---|---:|---:|---:|
| 0 | 119 mm | 16.686920829° | 0.01563698117 |
| 19 | 126 mm | 15.641889639° | 0.01478462680 |
| 28 | 129 mm | 15.600387269° | 0.01491706808 |

这些是从此组图像求得的拟合值，不是可以套到所有腾龙镜头上的标定数据。

自动调平保持默认开启。拍摄环不满足一致性要求，因此转用 Hugin straighten，施加约 **1.208301511°** 的共同旋转；逐张旋转不变量检查的最大矩阵误差约 `8.07e-12`。

颜色阶段固定已统一的白平衡，优化重叠曝光及镜头组暗角，并给本组输出增加 1 EV。最后将工程提升到全尺寸 TIFF，使用圆柱投影和原生画布裁切导出。

## 几何结果应怎样解读

| 统计量 | 工作图阶段，等效工作图像素 | 提升后，等效原图像素 |
|---|---:|---:|
| 点数 | 1234 | 1234 |
| 中位数 | 1.3783 | 4.1513 |
| 均值 | 1.7616 | 5.2892 |
| P95 | 4.6799 | 14.1165 |
| 最大值 | 10.3422 | 30.8738 |

两列使用同一批点，是不同源图尺寸下的拟合残差。原尺寸约为工作图三倍，残差也相应变化；这不是导出时突然失准，也不能当成独立检验得出的绝对精度。按角度折算的源图像素残差不等于输出画布上的所有位置都偏移同样像素。

只优化 HFOV、未加几何 `b` 的前一版，工作图残差中位数约 3.8421 像素；加入各组 `b` 并重新优化后约为 1.3783。这里比较的是拟合模型和该数据的效果，不是不同算法的通用基准测试。

## 最终输出规格

原生画布为 **216065×14409**，PTO 裁切框为 `S0,216065,5472,10074`，顺序是左、右、上、下，右和下为边界。实际成品为：

**216065×4602 = 994331130 像素，约 9.94 亿像素。**

| 文件 | 尺寸 | 字节数 | 用途 |
|---|---|---:|---|
| `panorama_full_16bit.tif` | 216065×4602 | 4717633212 | 连续 16 位 BigTIFF 母版 |
| `panorama_full_01_01.jpg` | 54016×4602 | 88261472 | 原像素第 1 段 |
| `panorama_full_01_02.jpg` | 54016×4602 | 96108949 | 原像素第 2 段 |
| `panorama_full_01_03.jpg` | 54017×4602 | 87638191 | 原像素第 3 段 |
| `panorama_full_01_04.jpg` | 54016×4602 | 86118721 | 原像素第 4 段 |
| `panorama_overview.jpg` | 65000×1384 | 33173222 | 缩小到约 30.08% 的单张便览图 |

四段按文件名从左到右排列，起始横坐标分别为 `0,54016,108032,162049`，连续覆盖全部原生输出，没有重叠和缺口。JPEG 质量 97、4:4:4、sRGB。母版是 16 位三通道 RGB，Deflate 无损编码，带 sRGB ICC；其约 4.72 GB 指十进制体积。

没有输出一张 216065 像素宽的 JPG，是因为当前 JPEG 编码器不支持该边长；分段保持像素密度，便览图负责单张完整浏览。`preview.jpg` 更小，只用于快速看整体。

## 遇到的问题与对应修正

| 现象 | 找到的原因 | 最终处理 |
|---|---|---|
| 初始视场角接近 50°，与长焦明显不符 | 派生 JPEG 的部分光学 EXIF 写错 IFD 层级，Hugin 没读到实际焦距 | 正确写入 Exif IFD，并用 ExifTool 同步选定标签 |
| 匹配图连通，但部分照片翻转，HFOV 跑到约 6.95° | 海天弱纹理对应和逐对姿态初值不可靠；“连通”不代表每条边正确 | 增加射线旋转 RANSAC 验证和最大生成树初值 |
| 图像 26 缺少可靠连接 | 其相邻海面重叠特征弱 | 对指定邻接关系做 CLAHE/SIFT 补点，再通过同一旋转验证 |
| 仍有系统性几何残差 | 焦距变化和镜头畸变未充分表达 | 分三组优化 HFOV 与几何径向 b |
| 预览只显示整圈的一部分 | 不同尺寸下 Hugin 自动裁切选择了不同的矩形 | 以原生裁切框为准，再按比例设置预览裁切 |
| 个别窄边缘块的 Enblend 报错 | 极窄独占区域导致粗掩模接缝失败 | 只对已识别错误使用细掩模后备参数，两块重试后通过 |
| 超宽图无法保存为单张 JPG | JPEG 编码尺寸限制 | 连续 BigTIFF + 四段全像素 JPG + 缩小便览 JPG |

最终使用 `geometry_v6`、`color_v1`、修正覆盖后的 `preview_v2` 和 `final`。旧的 `geometry_v1`–`v5`、`preview_v1` 只作为本机实验记录，不是推荐复现路径。

## 已完成的检查与剩余限制

- 38 张原 ARW 的 SHA256 与处理时记录一致。
- 成品 TIFF 和全部 JPG 完整解码通过；检查了尺寸、位深、ICC 与分段覆盖。
- 两条拼合工作条带的 alpha 最小值均为 65535，裁切范围内没有未覆盖孔洞。
- 用 Hugin 原生变换检查 177 个点的圆柱整数平移，横移 72021 像素时最大横向误差约 `1e-6` 像素，纵向误差为 0。
- 检查了整体预览、分段图和原尺寸细节。远处薄雾、大气扰动与源照片里的局部模糊不会因拼接而消失，末段下方源图中的近景栏杆也被保留。

最终成功续算记录为约 569.6 秒，**包含缓存复用，不是从 RAW 开始的总耗时**。这组数据使用了显式补点对和案例专用圆柱配置，不能据此宣称任意拍摄轨迹都可全自动处理。验证方法与故障排查见 [验证说明](VALIDATION.zh-CN.md)。
